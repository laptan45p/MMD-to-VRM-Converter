# MMD-to-VRM-Converter

MMDのPMXモデルをVRM 0.xへ変換するWindows用ツールです。現在のバージョンは **0.9.4** です。

### 表情の自動登録

左右の口角が別モーフの場合も、両側が揃っていれば組み合わせて使用します。全体の口角モーフがある場合はそちらを優先し、二重に適用しません。「組み合わせ候補が未検出」は、喜怒哀楽の素材として名前を対応できない部分があるという意味で、モーフの消失を示すものではありません。未使用の頂点モーフも、名前付きの追加表情として登録します。笑顔用の眉など、対応するモーフがない部分を別の形で無理に埋めることはしません。

喜怒哀楽は、見つかった目・眉・口のモーフを組み合わせて登録します。各パーツでは候補名の優先順位に従い1種類を選び、同じモーフの重ね掛けを防ぎます。存在しないパーツは省略します。まばたき・左右ウインク・母音の口パクも対応する名前から設定します。

さらに、出力された全頂点モーフを元の名前でカスタム表情に登録します。ハート目・涙・赤面なども、対応する頂点モーフがあれば個別に呼び出せます。標準プリセット名と重なる名前には `MMD_` を付けます。カスタム表情を選べるか、自動会話で使うかは利用アプリ側の対応によります。

変換後の `.conversion.json` の `expressionReport` で、各プリセットの使用モーフ・強度・不足パーツと追加表情の一覧を確認できます。`complete` は候補が揃ったことを示し、見た目の完全再現を保証するものではありません。自動設定は初期値なので、口パク・まばたきと組み合わせた際の見た目も確認してください。材質モーフによる色・透明度の変化とボーンモーフは引き続き未対応です。表情のプレビュー・強度編集画面は含みません。

Windowsの画面からBlenderをバックグラウンド起動し、モデルの読み込み、基本材質の変換、人型ボーンの対応付け、Tポーズの焼き込み、VRM出力を行います。

## 必要なもの

- WindowsとWindows PowerShell 5.1（起動スクリプトは標準の`powershell.exe`を使用）
- Blender（開発時にユーザーが使用したバージョン: 5.2.2 LTS）
- Blenderにインストールした[MMD Tools](https://github.com/MMD-Blender/blender_mmd_tools)
- 改変・形式変換が許可されたPMXモデルと、そのテクスチャ

通常の利用では、Pythonを別途インストールする必要はありません。Blender付属のPythonとNumPyを使用します。VRM Add-onも不要です。

## 起動と変換

1. Blenderで「編集 → プリファレンス」を開き、必要に応じてオンラインアクセスを許可します。
2. 「エクステンションを入手」で **MMD Tools** を検索し、インストールします。
3. このリポジトリをダウンロードまたはcloneし、書き込み可能なフォルダに配置します。
4. `start.bat`をダブルクリックします。
5. `Blender.exe`、入力PMXまたはZIP、保存先を選択します。
6. 元モデルの作者名と、必要に応じて利用条件URLを入力します。揺れの部位と数値を設定し、「変換開始」を押します。

ZIPにはPMXを1つだけ入れてください。複数のPMXがある場合は、展開して使用するPMXを直接選択してください。

テクスチャの相対パスは保持してください。PMXとtextureフォルダが並ぶ構成にも対応します。ZIPを選択した場合は、そのZIPの展開範囲内でテクスチャを解決します。PMXを直接選択した場合、親フォルダ名が`PMX`、`model`、`models`なら1つ上をモデルの範囲とし、それ以外はPMXの親フォルダを範囲とします。

## 出力

| 出力 | 内容 |
| --- | --- |
| 指定した`.vrm` | VRM 0.xモデル |
| 同名の`.conversion.json` | ボーン、表情、注意事項などの変換情報 |
| `logs/日時/` | 処理ログ、展開したモデル、中間GLB、ジョブ設定 |
| `settings.json` | Blenderの場所、作者名、利用条件URL、揺れ設定 |

ログ画面で進捗を確認でき、停止ボタンで変換を終了できます。元のPMXやZIPは書き換えません。既存VRMを上書きするときは確認画面が表示されます。

## 対応範囲

- PMX 2.0 / 2.1の読み込み（MMD Toolsを利用）
- 基本テクスチャ、色、透明度、スキンの変換
- 標準的なMMDボーン名から人型ボーンへの対応付け
- VRM 0.x向けのボーン回転・スケールの正規化とスキン行列の再生成
- 腕を水平にしたTポーズと頂点モーフの焼き込み
- 頂点モーフの標準名によるまばたき・母音などのプリセット設定
- テクスチャのアルファから不透明・切り抜き・半透明を分類
- 指ボーン名の全角数字・人差指表記の対応と手首からの階層検証
- 髪・リボン・袖・スカート・胸のVRM 0.x Spring Bone仮設定
- ZIPパスの検証、展開サイズ上限2GB

## 素体のみモード（実験機能）

元MMDの頭・顔・髪を残し、別のVRMの体を骨格に合わせて組み合わせます。元モデルにない体を生成する機能ではありません。

1. 入力PMX / ZIPと保存先を選びます。
2. 変換モードを「素体のみ（実験機能）」に切り替えます。
3. 「補完素体」に体のあるVRM 0.x、FBX、またはそれを1個含むZIPを指定します。VRM 1.0は未対応です。
4. 「体メッシュ名」はまず空欄で試してください。特定できない場合はログの候補から正確な名前を入力します（例: `BodySkin.baked`）。
5. 必要なら首の境界補正（m）、体の幅・厚み倍率を調整します。
6. 「体型・肌色」ボタンで部位別倍率と肌色補正を設定し、変換します。

補完素体は頭と体が別メッシュになっている構成を推奨します。体と服が一体のメッシュから服を分離する機能はありません。補完用VRMは利用者が指定し、ツールには同梱しません。

体は人型ボーンの位置・長さを基準に合わせます。腰と背骨の操作用ボーンが同じ位置や極端に高い位置にある場合は、脚の付け根と首の間に補完素体の胴体比率を当てはめ、腰の潰れを抑えます。元MMDの操作用ボーンの位置は変更しません。補完素体の強い縁取り・発光・固有の陰影マップは引き継がず、基本の肌材質へ統一します。指の対応が不足する場合、補完素体から対応可能なボーンを追加します。胸ボーンとウェイトも利用し、揺れは画面の設定から再設定します。補完VRMの元の物理数値をそのままコピーする機能ではありません。

元MMDの頭はボーンのウェイトと首の高さから推定して保持します。頭に追従する襟・装飾が残ったり、非標準のウェイトで髪などが欠けたりする場合があります。首の境界補正は主に首ウェイトの面に作用し、正の値で境界を上げます。境界は面単位で選別します。首の自動接合が有効なら、対応可能な輪状の境界に接続面を追加します。任意の構造を自動溶接・穴埋めする機能ではありません。肌色・首の太さ・つなぎ目・動作時の見た目は調整が必要です。体の幅・厚み倍率は各ボーン周りの断面を調整する目安です。

元MMDの保持した頭の表情モーフは残します。補完素体の表情・体形モーフは移植しません。「服付きのまま内側に素体を追加」はこの版では未対応です。

補完素材の作者・利用条件URL・メタデータをVRMの参照情報や変換レポートに記録します。元MMDと補完素材の両方の利用条件が適用されます。素材の情報を追加しても利用許諾を取得したことにはなりません。

素体のパスと調整値は保存しますが、次回起動時のモードは通常変換に戻ります。

## 素体に頭部を移植するモード（実験機能）

補完素体の体型と骨格を基準にし、元MMDから頭・顔・髪を移します。元MMDの体型への一致は優先しません。従来の「素体のみ」は元MMDの骨格へ体を合わせる方式で、このモードは補完素体の骨格へ頭部を合わせる方式です。

1. 入力に元MMDのPMX / ZIP、補完素体にVRM 0.x / FBX / ZIPを指定します。
2. 変換モードを「素体に頭部を移植（実験機能）」にします。
3. 「頭部の大きさ倍率」はまず **1.0**、「首の境界補正」は **0** で変換します。
4. 必要なら頭部倍率を0.05ずつ調整して再変換してください。倍率は首の位置を基準とする一様な拡大縮小です。

素体をTポーズへ正規化した後、体の頂点・ウェイト・骨格はそのまま使います。素体側の頭は除去し、MMD側の頭部を首へ位置合わせします。頭部の基準スケールは両モデルの首から足首までの高さで単位差を調整します。表情モーフの変位にも同じ倍率を適用し、髪のボーン階層を素体の頭ボーンへ接続します。

材質名に `hair`・「髪」・「もみあげ」・「アホ毛」を含む髪の面は、首より下や体側ボーンのウェイトがある場合も保持します。頭の子になっていない髪のボーンとその末端も移植し、体側の操作用ボーンに付いた髪のウェイトは頭へまとめます。髪が肌・衣装と同じ材質を共用する構成や、独自の材質名は自動判定できない場合があります。髪材質名と保持した面数を変換レポートに記録します。

このモードでは、従来の体型・断面・肌色補正は適用しません。頭部と体の肌画像はそれぞれ保持し、素体側のリムライト・輪郭線などは従来と同じ基本材質へ標準化します。揺れは画面の設定から再設定します。元の物理設定・体形モーフは引き継ぎません。

首の自動接合は利用できます。有効時は体側の首付近の頂点・法線・ウェイトを調整し、接続帯を作ります。首以外の体型を頭に合わせて変形させる処理はありません。境界の構造によっては接合を省略します。首の肌色・陰影や頭の大きさは調整が必要で、自然な仕上がりを保証する機能ではありません。

変換レポートの `conversionMode` は `head_to_template`、`bodyTemplateReport.assemblyBasis` は `template` です。頭部倍率・平行移動量・接合結果も記録します。起動直後のモードは通常変換です。

## FBX / ZIPの補完素体

「補完素体」欄で `.fbx` または `.zip` を選択できます。元MMDの入力欄は従来どおりPMX / ZIPです。

- ZIPにはVRMまたはFBXを1個だけ入れてください。フォルダ構造は維持します。
- FBXはアーマチュア1個、体メッシュの肌材質1個の構成を対象にします。体メッシュが複数ある場合は名前を指定します。
- `BaseBody/Skin1.png` があれば、その同梱テクスチャを優先します。`Body_Cloth` は自動選択しません。新しい肌の模様やディテールは生成しません。
- 他の肌色を使う場合はZIPを展開し、「FBX設定」で肌テクスチャを選択してください。選択した肌画像を体の材質に設定します。
- FBXに必要な肌テクスチャが見つからない場合は、画像を明示的に指定してください。PSDやUnityパッケージは読み込みません。
- FBXの元のシェーダーは再現せず、肌画像を使う基本材質に置き換えます。FBXの体形モーフはこの版では移植しません。
- FBX入力で手動の肌材質名を指定する場合、準備後の材質名は通常 `FBXTemplateSkin` です。まずは空欄で試してください。
- `L_UpperArm`、`R_hand`、`L_thumb_proximal` などの英語ボーン名を対応付けます。独自名は未対応の場合があります。

FBXにはVRM形式の作者・利用条件情報がないため、「FBX設定」で補完素材の作者と利用条件URLを入力してください。省略時は作者を未指定としてレポートに警告します。入力内容は許諾を取得したことにはなりません。

FBXはBlender上で一時的にVRM 0.xの構成へ準備し、その後、体形調整・肌色補正・首の接合へ進みます。FBXそのものや元テクスチャは変更しません。BlenderのFBXインポートを含む通し実行は開発環境では未確認です。

## 体型・肌色の調整（素体モード）

「体型・肌色」から設定します。「元MMDの骨格・肌形状に体型を合わせる」は初期値でオンです。

肩の高さ・肩幅・脚の付け根の間隔を基準に、補完素体のバランスを調整します。元MMDに肌材質の形状が残っている部位は、胴の高さ別の幅・厚みや腕・脚の太さも測ります。頭・顔・髪と元MMDの骨格の位置、脚・腕の長さは維持します。

肌材質の候補は名前に `skin`・「肌」・「素体」を含む材質です。「元MMDの肌材質名」で明示もできます。衣装材質は自動測定から除きます。肌の片側しかない断面や頂点が不足する部位は測定せず、骨格幅を使い、胴の厚みは維持します。片方の腕・脚だけ十分に測れる場合は、その太さを反対側にも使います。補正倍率は0.65〜1.35に制限し、胴の断面補正は高さ方向になだらかにつなぎます。衣装の下に存在しない素体や元の体型を完全に復元する機能ではありません。

体型の倍率1.0は自動補正後の形です。部位別倍率と全体の幅・厚み倍率でさらに調整できます。従来の合わせ方を使う場合は、この自動補正をオフにしてください。設定は保存され、測定方法・補正量は変換レポートの `bodyTemplateReport.proportionMatching` に記録します。

| 項目 | 初期値 / 範囲 | 動作 |
| --- | --- | --- |
| 胸のボリューム | 1.0 / 0.5〜1.5 | 胸のウェイトや位置を基準に肉付きを調整。追加した胸ボーンも追従 |
| ウエスト | 1.0 / 0.5〜1.5 | 胴の中央付近の幅・厚みを調整 |
| 腰・お尻 | 1.0 / 0.5〜1.5 | 腰周りの幅・厚みを調整 |
| 太もも | 1.0 / 0.5〜1.5 | 股関節〜膝の間の断面を調整 |
| 二の腕 | 1.0 / 0.5〜1.5 | 肩〜肘の間の断面を調整 |
| 首の太さ | 1.0 / 0.5〜1.5 | 首付近の幅・厚みを調整。元モデルの頭側は変更しない |
| 肌色の自動補正 | オン | 元MMDの肌材質の代表色へ補完素体の肌を近づける |
| 補正の強さ | 0.8 / 0〜1 | 0で無補正、1で代表色へ強く寄せる |
| 元MMD / 補完VRMの肌材質名 | 空欄 | 空欄で名前から推定。指定時は正確な材質名を使用 |

肌色はUV上の複数箇所をサンプルし、透明部分・濃い線・彩度の高い部分を除いて代表色を選びます。選んだ補完肌材質のベースカラーと陰影用テクスチャを色補正し、アルファを保持します。法線マップは色補正しません。元MMDのテクスチャは変更しません。

肌材質や色を自動検出できない場合、肌色補正だけを省略してログに候補を表示します。誤った材質名を明示した場合はエラーで知らせます。ひとつの肌材質が対象です。目・髪・衣装などと肌が同じ材質・テクスチャを共用している補完素材には適しません。補正量は極端な変色を防ぐため制限します。

照明やMToonの陰影まで完全一致させる機能ではありません。大きく形を変えると凹み・面の重なり・首の段差が出ることがあります。0.05〜0.1程度ずつ変更して再変換し、動作を確認してください。胸のボリュームと揺れの硬さ・減衰は別の設定です。

設定は保存します。「初期値に戻す」で、この画面の項目を基準値に戻せます。体型・補正対象材質・代表色・補正結果は変換レポートに記録します。

肌テクスチャの読み書きにはBlender標準の画像機能を使用します。通常利用にPillowの追加インストールは不要です。開発用の画像テストではPillowを使用します。

## 首の自動接合（実験機能）

素体モードの「体型・肌色」にある「首を自動接合する」で切り替えます。初期値はオンです。通常変換には適用しません。

頭側と体側で首に近い輪状の境界を検出し、体側の形を頭側に合わせて接続面を追加します。境界の頂点数が異なる場合も対応します。体側の変形を周辺になだらかに広げ、法線をそろえ、境界のウェイトを接続帯にも引き継ぎます。元の頭の位置は変えません。

首の境界候補が複数、面の向きが不整合、境界に表情モーフがある、頂点のウェイトが矛盾、変形で面が反転するなどの場合は接合を省略し、接合前の素体合成結果を出力します。対象外の形状を無理に接合する機能ではありません。

接続帯は肌の代表色を使う単色の材質です。元の肌模様の復元や、色・陰影の境目を完全に消す処理ではありません。境界を一つの編集用メッシュに統合する頂点溶接ではなく、幾何的に隙間を埋める接続帯です。大きな首の太さ・位置の差や独自構造には対応できない場合があります。

ログと変換レポートの `bodyTemplateReport.neckJoin` に `joined`（接合）、`skipped`（省略）、`disabled`（オフ）を記録します。省略時は理由も確認できます。首の角度や表情を動かして確認してください。

Tポーズ正規化では、腕を胴体から外側へ伸ばすように左右の位置から方向を判定します。目のボーンがある場合は前方向を補正し、ない場合は元の前方向を保持します。

## 揺れと指の設定

部位のチェックを外すと、その部位の揺れを出力しません。胸の初期値は硬さ2.5・減衰0.6・重力0・半径0.006です。保存済み設定がある場合はそちらを優先するため、既存環境では胸の数値を変更してください。

| 数値 | 調整の目安 |
| --- | --- |
| 硬さ | 大きいほど元の姿勢に戻ろうとする力が強い |
| 減衰 | 大きいほど揺れが早く収まる |
| 重力 | 大きいほど下向きの力が強い |
| 半径 (m) | 揺れるボーンの衝突半径。モデル身長に応じて補正 |

髪・衣装には頭や胴体、脚の球形コライダーを仮設定できます。胸には自己衝突による跳ねを避けるためコライダーを割り当てません。衣装の貫通防止を保証する設定ではありません。

ボーン名と階層からの推定であり、MMD物理設定の移植ではありません。対応ボーンと子ボーンが必要です。ボーンの追加やウェイト修正はしません。独自名のボーンは検出されない場合があります。部位が混在する子階層は親の分類に従います。検出結果・除外理由・設定値は変換レポートに記録します。出力したVRMを配信アプリで確認し、必要に応じて数値を調整して再変換してください。

Webカメラの手・顔トラッキングは配信アプリ側で行います。このツールはVRM内の指ボーン対応と揺れ設定を準備します。

## 未対応・制限

- PMD入力
- MMD剛体・ジョイント設定の完全な再現
- 材質モーフ、ボーンモーフ、グループモーフの完全な再現
- MMDのToonテクスチャ、スフィアマップ、輪郭の正確な再現
- 独自のボーン名や複雑な構成の全モデルへの対応
- VRChat用設定、SDKによるアップロード、Quest向け最適化

VRMに変換しただけではVRChatへ直接アップロードできません。UnityでVRChat向けの設定が別途必要です。

## PMXの固定ボーンと揺れの判定

元PMXの剛体モードを読み、ボーン追従型の固定ボーンと物理型のボーンを区別します。剛体を持たず、剛体ボーンを束ねる親は操作用の親として扱います。固定・操作用の親はSpring Boneにせず、その下の毛束などを個別に揺らします。固定ボーンが途中にある連鎖では、その固定点より上から再帰的に揺らさないようにします。

この判定は通常変換と両方の素体合成モードに適用します。頭部移植では髪ボーンの固定・物理の区別も移植します。元の剛体の質量・衝突形状・ジョイントの完全再現ではなく、揺れの数値は画面の設定を使います。PMXの手掛かりがない部位は従来の名前による仮設定です。同一ボーンに固定と物理の両方がある場合は固定を優先します。

変換レポートの `pmxPhysicsHints` に判定数、`springBoneReport.skipped` に `pmx_fixed` / `pmx_control` / `contains_fixed_anchor` などの除外理由を記録します。以前のVRMを読み直すだけでは更新されないため、元PMX / ZIPから再変換してください。
